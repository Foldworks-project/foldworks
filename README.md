# Foldworks

> **A self-hosted visual catalogue for collecting, organizing, discovering, and building paper models.**

Foldworks is an open-source application for people who collect and build paper models.

Paper-model collections rarely consist of neat, uniform files. A single model may include a PDF, Pepakura PDO, instruction booklet, image sheets, textures, reference images, photographs, source archives, or several alternate versions.

A filesystem can store those files.

**Foldworks understands that they belong to a model.**

## The idea

The fundamental object in Foldworks is the **model**, not the file.

A model can have identity, metadata, presentation, build information, relationships, and any number of associated assets.

Foldworks is intended to turn a directory of paper-model files into a collection that can be:

- browsed visually;
- searched meaningfully;
- organized without requiring perfect metadata;
- enriched with format-specific information;
- preserved without surrendering ownership of the original files.

The goal is not merely to find files.

The goal is to make a paper-model collection a place worth exploring.

## PDO is an enhancement, not a requirement

Pepakura PDO is important to the paper-model community, and Foldworks intends to understand the format deeply.

Future PDO support may include metadata extraction, textures, geometry, unfolded layouts, automatic renders, and interactive visualization.

But PDO does **not** define Foldworks.

PDF-only models, image-sheet models, scans, SVG-based models, and formats Foldworks only partially understands must remain first-class models with a complete and attractive experience.

## Your collection belongs to you

Foldworks is built around user ownership and data portability.

Where practical, self-hosted Foldworks will catalogue ordinary user-owned files rather than hiding collections inside an opaque proprietary store.

Foldworks may manage storage where appropriate, particularly in hosted environments, but storage management must never become ownership.

Users must be able to export their data and leave.

**Foldworks must never hold a collection hostage.**

## Self-hosted and hosted

There will ultimately be **one Foldworks**.

Self-hosted Foldworks gets the complete application.

Foldworks Cloud will offer the same application as a managed service for people who would rather pay for hosting, storage, backups, upgrades, monitoring, infrastructure, and convenience than operate it themselves.

Cloud customers will not pay to unlock application features deliberately withheld from self-hosted users.

## Built with AI

Foldworks is also an experiment in **AI-assisted boutique software development**.

The project asks whether generative AI can reduce the organizational and engineering cost of software development enough for individuals with deep domain knowledge to build excellent software for communities traditionally considered too small to support dedicated applications.

Foldworks is being **built with AI**, not merely generated by AI.

AI may contribute substantial engineering, research, architecture, testing, review, and documentation capability. Human judgment remains responsible for product direction, verification, acceptance, and ownership.

The project intends to document both the successes and failures of that process openly.

See [BUILT_WITH_AI.md](BUILT_WITH_AI.md).

## Project status

**Foldworks is currently in product specification and pre-development.**

Application implementation has intentionally **not begun yet**.

The project is establishing its product model, UX requirements, architecture, engineering standards, and development process before implementation begins.

The first implementation milestone will be one excellent vertical slice:

```text
Install Foldworks
    ↓
Create account
    ↓
Import an ordinary PDF paper model
    ↓
Generate an attractive preview
    ↓
Edit metadata
    ↓
Browse the model
    ↓
Open the model
    ↓
Access the original files
    ↓
Find it through search
```

Once that workflow works well, Foldworks can grow outward from something real.

## Product Constitution

Foldworks has a ratified Product Constitution defining the principles future product, architecture, engineering, and business decisions must respect.

Read:

**[Foldworks Product Constitution](PRODUCT_CONSTITUTION.md)**

Among its foundational principles:

- the model, not the file, is the fundamental object;
- PDO is progressive enhancement;
- non-PDO models receive a first-class experience;
- user files and data belong to the user;
- export must always be possible;
- self-hosted Foldworks gets the complete application;
- Foldworks Cloud sells operations, not artificial software scarcity;
- multi-user support is a Foldworks feature, not a Cloud feature;
- tenant awareness comes early, SaaS complexity later;
- automation must never make manual organization impossible;
- the repository is the project's institutional memory;
- AI-generated implementation must be tested and reviewed;
- the project will document AI successes and failures honestly;
- Foldworks will not solve hypothetical success before success exists;
- one excellent vertical slice comes before trying to build everything.
